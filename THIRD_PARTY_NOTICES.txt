STEP 3 ADDITION
The existing uprotocol 0.1.0-ALPHA35 source artifact was inspected again at
org/monora/uprotocol/core/transfer/Transfers.java, receive(). That path opens a
PersistenceProvider output stream, writes transfer buffers to it, persists item
status and installs received content. This application replaces that consumer
boundary with RelayPacketFilter's borrowed direct-buffer local/next-hop callback.
Those persistence, file descriptor, resume and content-install operations are not
included. This is an architectural adaptation, not a claim that TrebleShot itself
ships a silent mesh relay. No Transfers.java source was copied.

RelayPacketFilter.kt and SilentRelayService.kt are supplied under GPL-2.0-or-later,
consistent with the existing adapted connection layer. Step 3 also modifies the
existing packet codec to version 2 remaining-TTL semantics and updates the manager
to support synchronous raw-frame forwarding with the same socket write lock as
heartbeats. It does not introduce a second framing or media-reassembly engine.

STEP 4 ADDITION
Re-inspected Transfers.java receive() and send() in the same uprotocol artifact.
Upstream uses transfer IDs, source-length checks, bounded stream reads, offsets
and an endpoint persistence provider. The requested 512 KiB/fragment metadata,
SHA-256 completion check, reverse mesh breadcrumbs and two-lane scheduler are
new application-specific adaptations, not features copied verbatim from upstream.
ChunkManager.kt retains the streaming/offset lifecycle using standard FileChannel
and RandomAccessFile. It does not reproduce upstream resume/database semantics.
AckManager.kt and PriorityQueueManager.kt integrate with the existing mesh codec
and connection engine. All three new source files are GPL-2.0-or-later, consistent
with this adapted project. No additional upstream source was copied in Step 4.
