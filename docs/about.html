01 / Connection path

एक peer से दूसरे peer तक

Two nearby devices can establish a direct Wi-Fi Direct session after the receiving user accepts. In a fully integrated relay deployment, intermediate nodes would pass frames to the next available hop. Every link must work independently; adding nodes does not guarantee a continuous route.

Node discovery

Wi-Fi Direct discovery and DNS-SD local service records advertise peer identity and cluster metadata. Discovery is not a GPS/range measurement.

Handshake & consent

App hello and explicit Accept / Reject gate the direct channel. Voice and file requests use consent checks. E2EE key exchange remains future work.

Security boundary ↓

Bounded relay

Configured routes select the next hop. RAM buffers, duplicate detection and a decrementing TTL bound forwarding. No persistent offline store-and-forward queue is implemented in the relay.

Delivery ACK

The transfer receiver checks completion and SHA-256 before reporting delivery. ACK packets travel back through the transport; timeouts do not mean delivery succeeded.

02 / Data in motion

Messages, voice और files

Direct transport

Text & JSON chat

Native peers exchange binary MeshPacket frames over TCP. The gateway translates browser JSON messages over WebSockets. Local chat does not require a remote chat server, but radio, queueing and processing latency still exist—latency is not zero.

Foreground audio

Voice notes & live audio

The voice engine streams short encoded audio packets through the priority lane. Browser audio uses supported MediaRecorder formats. Delay depends on codec support, devices and network conditions; no fixed latency guarantee is established.

Chunked transfer

Video, ZIP & large files

The native sender reads 512 KiB chunks, then fragments them into payloads up to 32 KiB to fit the existing binary frame. Receivers assemble approved transfers in app cache and verify SHA-256. 50+ Mbps is a proposed performance target, not a measured result.

Routing primitives

TTL, duplicates & route freshness

Frames carry a UUID, identities, cluster, remaining TTL, hop count and CRC32. The default hop budget is 25. The relay drops duplicates and expired/no-route frames; durable buffering for disconnected destinations is not provided.

03 / Trust boundaries

Privacy & security: क्या लागू है?

Implemented boundaries

Consent & local data

Peer consent controls admission. Relay forwarding uses bounded RAM instead of writing forwarded payloads to disk. Endpoints may cache files locally. Browser access to a configured remote gateway requires trusted HTTPS; signing verifies APK provenance.

Not implemented end-to-end

AES-256-GCM / E2EE

The inspected native MeshPacket/TCP path does not encrypt message payloads end-to-end or implement authenticated peer key exchange. CRC32 and SHA-256 are integrity mechanisms, not encryption or peer authentication. HTTPS protects the browser-to-gateway leg, not the entire mesh route.

The GitHub-native application does not wire an installation-telemetry uploader. However, remote configuration/update checks and this website’s GitHub statistics requests use the internet when available. GitHub receives those requests. “Zero cloud telemetry” should not be read as “zero external requests.”

04 / Specifications & targets

Coverage depends on every link.

5 km is a deployment/design target, not demonstrated coverage. At a straight-line spacing of 120–150m, 5 km requires roughly 34–42 links, before obstacles and overlap. That exceeds the current 25-hop packet budget. Ten to thirty-five dynamic hops therefore cannot be presented as a supported 5 km guarantee. Range and routing changes need field testing and implementation work.

05 / Where local connections help

कहाँ और कैसे इस्तेमाल करें?

These are potential uses for tested local links—not a guarantee of emergency service availability. Plan power, nearby peers and a fallback communication method.

Emergency coordination

आपदा और स्थानीय मदद

बाढ़, भूकंप या तूफ़ान में जब tower सेवा बंद हो, पास मौजूद टीमों के बीच local messages उपयोगी हो सकते हैं। App को verified rescue या emergency-call system का विकल्प न मानें।

Remote communities

ग्रामीण और दूरदराज क्षेत्र

कमज़ोर इंटरनेट वाले स्थानों में पहले APK डाउनलोड करके nearby devices जोड़ें। दूर के गाँव तक connection तभी बनेगा जब हर आवश्यक radio link और relay route उपलब्ध हो।

Public gatherings

रैलियाँ, मेले और events

भीड़ में mobile-network congestion के दौरान आसपास की टीम से direct chat करें। Local Wi-Fi पर भी interference हो सकता है—पहले छोटे समूह में परीक्षण करें।

Field teams

Trekking, camping और निर्माण

एक-दूसरे की radio range में रहकर coordination और files साझा करें। पहाड़, दीवारें और battery limits ध्यान में रखें; चलते हुए relay chain कायम रहने की गारंटी नहीं है।
